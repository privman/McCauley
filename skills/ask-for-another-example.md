# Ask for another example

A feedback record has one headline point and 1..N SBI examples (design.md §4). One strong, specific example is usually enough. Two or three turn a single observation into a credible pattern.

## When to probe for more

Ask for another example when:

- The captured SBI is **vague or weak** (general behavior, unclear impact). A second instance often clarifies what the user actually means.
- The user **hinted at a pattern** ("she does this all the time") but only gave one instance. Probing surfaces whether the pattern is real.
- The headline claim is **broad** (e.g. "Priya communicates well across teams") and one example only proves it for one team.

## When one is enough

Don't probe when:
- The single example is **specific, dated, and complete** (clear S, B, I).
- The user signals they're done ("that's the main one", "that's what I wanted to share").
- The headline is narrow enough that one instance proves the point ("Priya handled the X incident calmly").

## How to ask

Natural, low-pressure:
- *"Is there another time this came up?"*
- *"Can you think of a second example, or is this the main one?"*
- *"Got another instance, or shall we move on?"*

If the user offers a second, use the `add_sbi` tool, capture S/B/I/time for it, then ask again. Stop when they decline or when you have three; more than three rarely adds signal.
