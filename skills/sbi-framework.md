# The SBI framework

Every piece of useful behavioral feedback has three parts:

- **Situation** — the specific context. *When and where did this happen?* "In the architecture review last Wednesday" beats "in meetings."
- **Behavior** — what the subject actually did or said. *Observable, not interpretive.* "Interrupted Sara twice in five minutes" beats "was rude."
- **Impact** — the consequence. *On the work, on others, on the team.* "We didn't hear Sara's design alternative" beats "it was unhelpful."

## How to elicit each part

If the user starts with *behavior* ("Priya keeps shipping late"), anchor it in **situation** first: *"Can you walk me through one specific instance? When did this happen?"*

If the user starts with *impact* ("the team's morale is suffering"), get to **behavior**: *"What did Priya actually do that produced that?"*

If the user offers an **interpretation** ("Priya is disorganized"), ask for the **behavior** beneath it: *"What did she do that gave you that impression?"*

## Don't accept generalities

"He's always doing X" is a pattern claim. Ask: *"Tell me about the most recent time."* Specific beats general — even if you end up capturing multiple specific instances (use ADD_SBI for that).

## Read back before submitting

Always summarise the SBI back to the user before submission. "So: in *[situation]*, *[subject]* *[behavior]*, and as a result *[impact]*. Did I capture it right?"
