# v0.1 Scope — Demo Build

## Goal

A working end-to-end demo of the feedback agent that runs locally and is suitable for showing the product to stakeholders. Not production: no multi-tenant deployment, no real auth integration, no compliance posture, no scale-out story.

The v0.1 build is the smallest thing that lets a viewer experience:

- A provider giving structured (SBI) feedback about a peer with help from the LLM, including pivoting between drafts mid-conversation.
- A recipient querying the feedback they're authorized to see and getting cited, grounded answers, including a generated report.
- The ACL correctly partitioning what each user can see.

**No throwaway work**: every module here is a stepping-stone to v1 in [design.md](design.md). Where v0.1 diverges from the design, the divergence is in *what is absent*, not in code that will be ripped out.

## What's out (deferred, see [design.md](http://design.md) for v1)

- **Multi-region deployment, GKE, Terraform.** Local docker-compose only.
- **Real auth** (OIDC, customer IdPs). See Simplifications.
- **SCIM / HRIS connectors.** Seed CSV instead.
- **Audio persistence and retention policy.** Audio is streamed in, transcribed, used to drive the conversation, and dropped. No GCS storage of raw audio in v0.1 (the transcript in `conversation_turns.content_text` is the only durable record).
- **CMEK/KMS, mTLS, sub-processor DPAs, residency disclosures.**
- **Topic-taxonomy HR operations** — `add`/`rename`/`drop`/`merge`, suggestion queue, backfill jobs (design.md §4.4). v0.1 has a fixed seeded list and no operations on it.
- **Provider-injection defenses 4-11** from [design.md](design.md) §6.1 — submit-time screening, spotlighting wrappers, output filters, verifier passes, UI neutralization layer.
- **Constrained report template with programmatic verbatim-quote extraction** ([design.md](design.md) §6.1 defense #4). v0.1 `generate_report` returns a markdown skeleton that the model fills in end-to-end, *including* the quote selection — the "exact substring" guarantee is enforced only by a prompt rule, not by code.
- **Multilingual.** English only.
- **Anonymity split-table** (`anonymous_conversation_owner`). See Simplifications.
- **Premium voice tier, ElevenLabs fallback, on-prem Whisper.**
- **Async/queued work** (Redis, Redis Streams). Everything synchronous.
- **Frontend test suite** (Playwright, axe-core, bundle budgets, i18n coverage). Manual demo testing.
- **Load tests, behavioral LLM evals, security tests** including the §6.1 defense-3 red-team injection corpus in CI and the provider-injection defenses.
- **Observability** beyond stdout logging (no Langfuse, no OTel, no Grafana).
- **Audit log tables** (`access_log`, `admin_audit_log`) from [design.md](design.md) §4.1 and §9. v0.1 emits debug/info lines to stdout for every WS turn and tool call, but does not persist a queryable audit trail. The schema is in design but no migration creates the tables and no code writes to them. Adding them is a v1 step alongside other SOC 2 / DPA work.
- **§13 post-v1 improvements.**

## Simplifications (v0.1 ≠ design.md)

Where v0.1 actively differs from the design (not just omits). All chosen so the v1 path is additive, not destructive.


| Simplification                                                                                                                                                    | Why it's not throwaway                                                                                                                                                                                                                                                                     |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Single FastAPI process** instead of the Provider/Recipient/Speech/Org service split                                                                             | Module boundaries kept clean (`provider/`, `recipient/`, `org/`); the service split is a deployment concern that can happen later without rewriting handlers.                                                                                                                              |
| **Local auth — a "log in as" dropdown** listing seeded users, sets a signed session cookie                                                                        | The auth seam is a middleware that sets `app.current_user_id`; replacing the form with an OIDC handler is a one-file change downstream of everything else.                                                                                                                                 |
| **Anonymous feedback stored with `provider_user_id = NULL`**, no `anonymous_conversation_owner` table                                                             | The split table is only needed for compliant abuse investigation; adding it later doesn't require data migration since `provider_user_id` stays null in either model.                                                                                                                      |
| **Single Postgres container**, no HA, no replicas, no per-region anything                                                                                         | Same schema as v1; the multi-region story is a deployment change.                                                                                                                                                                                                                          |
| **Closure recomputation by full rebuild** on every org-seed reload (one CLI command)                                                                              | Incremental rebuild on `manager_id` changes is a v1 optimization. The function that computes `org_subordinates` from `users.manager_id` is the same one v1 will call incrementally.                                                                                                        |
| **Seeded demo corpus** — ~20 users, 5 org units, 15 pre-existing feedback records spread across the prior ~110 days (so the `date_range` filter is exercise-able) | Enough to exercise the closure logic and recipient retrieval credibly. The seed loader becomes a test fixture in v1.                                                                                                                                                                       |
| **Voice relayed through the backend** rather than the direct browser-to-Google path with ephemeral tokens described in [design.md](design.md) §3.2                | Demo concurrency is tiny so quota/egress aren't issues; ephemeral-token issuance is an optimization that can be added later without changing the conversation orchestration.                                                                                                               |
| **Half-duplex push-to-talk**, no barge-in, no mid-utterance interruption                                                                                          | Half-duplex matches the interviewer cadence the bot already targets; full-duplex turn-taking is a UX upgrade, not a different system.                                                                                                                                                      |
| **STT one-shot recognize** (Google v2 with `chirp_2`) rather than the streaming gRPC connection described in [design.md](design.md) §3.2                          | Push-to-talk has a natural end-of-utterance signal (mic release), so streaming buys only ~300–500 ms of finalisation latency and a live-caption UX. The transcribe() boundary is the same shape; switching to streaming is a v1 step that touches the WS handler but not the orchestrator. |
| **Conversation state lives in the FastAPI process memory** — orchestrator LLM history and the provider draft stack are held in a per-process `_active: dict[uuid, ProviderConversation/RecipientConversation]` and not persisted and load balancing across backend pods won't be possible; backend restart or switch drops both | The `conversations` DB row already survives, so the convo id is durable; the orchestrator content itself is what's transient. v1 will make the backend stateless: turns will persist to `conversation_turns` (schema already in [design.md](design.md) §4.1), drafts will go to a scalable transient store (Redis TTL or DB JSONB). The orchestrator's `step()` boundary and tool surface are unchanged — only the backing store moves, so this is an additive v1 step, not a rewrite. |


## Demo script (acceptance criteria for v0.1)

The build is shippable as a demo when this script runs end-to-end without manual intervention:

1. **Sign in as Sam** (IC, engineering).
2. **Provider mode (voice):** give feedback about Priya (Sam's peer's manager) by holding the mic button. Each utterance is transcribed live, the bot speaks back, and the live draft pane fills in turn-by-turn with subject, headline, and two SBI examples.
3. **Pivot mid-conversation** to feedback about the Mobile team (org unit), switching to text input to show that voice and text interleave per-turn. Draft pane shows the new draft; Priya's draft visible in the stack as paused.
4. **Resume Priya's draft** by clicking it; submit. DB shows: `feedback` row + 2× `sbi_instances` + 1× `feedback_chunks` with embedding; `sentiment` and `topic_tags` auto-populated against the seeded taxonomy.
5. **Submit the Mobile-team feedback anonymously.**
6. **Sign out, sign in as Maya** (Priya's manager — i.e. Sam's grandmanager).
7. **Recipient mode:** ask *"what feedback has come in about my reports this month?"* Bot retrieves Priya's feedback via the `org_subordinates` closure, grounds the response, shows sources panel with clickable citations.
8. **Probe the ACL:** ask about a sibling org Maya doesn't oversee. Bot returns no results (closure correctly excludes); the model does not invent content.
9. **Generate a report** — structured output with sentiment breakdown, top themes, verbatim quotes pulled from stored content.
10. **Sign in as Priya** — she sees her own feedback (self-pair in `org_subordinates`) but no feedback about her peers.

## Implementation notes (v0.1-specific)

- **Stack:** FastAPI + React (Vite + TypeScript) + Postgres 16 with `pgvector` + `pg_trgm` extensions. `docker-compose up` brings the whole thing up.
- **Voice transport:** see [design.md](design.md) §3.2 for the end-to-end audio path. The only v0.1-specific divergence is calling Google STT v2 `recognize` once per utterance instead of the streaming gRPC connection (see Simplifications). One Google Cloud service account, scoped to STT + TTS only, loaded from `.env`.
- **Auth seam:** every request goes through a middleware that issues `SET LOCAL app.current_user_id = $uid` on the DB connection. In v0.1 `$uid` comes from a session cookie set by the "log in as" form; in v1 it'll come from the OIDC handler. Code downstream is unaware of which.
- **Skills:** stored under `skills/*.md` with frontmatter (`name`, `when_to_use`); loaded at app startup via `load_skills()` in `main.py`; the index is injected into the Claude system prompt fresh each call (Anthropic prompt-caching is a v1 step — the SDK call site has the seam but no `cache_control` block yet).
- **Vector embeddings:** Voyage `voyage-3-large` called synchronously at submit time; vector stored in `feedback_chunks.embedding`. No async queue.
- **Lint/type in CI:** ruff + black + mypy (backend); ESLint + Prettier + tsc `--strict` (frontend). No coverage threshold yet.
- **Tests for v0.1 (minimum bar):**
  - Unit: closure-computation functions (`compute_org_subordinates`, `compute_unit_oversight`), SBI completeness validator (`FeedbackDraft.ready_to_submit`), skill loader.
  - Integration: a small seed-an-org → submit-feedback → query-as-different-users test that asserts each user sees exactly the records they should. This is the load-bearing correctness check; everything else is testable manually for v0.1.
- **No secrets in repo:** Anthropic, Voyage, and Google Cloud credentials read from a local `.env` (gitignored). README documents required env vars.
